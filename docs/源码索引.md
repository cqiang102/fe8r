> 而是"我以为语义是这样，实际源码里写着另一样"**。

> | 说"25 项全绿" | 从没验证过门禁真的**会失败** | 门禁假了很久 |

## ★ 事件脚本有**四层**，别只看一层

这是我卡最久的地方。一个脚本里的 `FADU` 要走完四层才能找到语义：

```
① 脚本宏          EventScr_Prologue_BeginningScene.c 里写  FADU
                            ↓  include/EAstdlib.h
② 语义名          #define FADU EvtFadeOutBlack
                            ↓  同一头文件里的 Evt* 宏
③ 编码            EvtFadeOutBlack → _EvtArg0(...) 展开成 opcode + 参数
                            ↓  include/eventscript.h
④ 指令 + 处理函数  EV_CMD_* 枚举 + [EV_CMD_X] = EventYY_Name
                            ↓
                  src/EventYY_Name.c  ← **真正的语义在这里**
```

**只看 ①④ 两层会漏掉 ②③。** 我最初就是拿 ① 的缩写名去 ④ 里搜，
搜不到（`SENQUEUE1`/`DISAX`/`BROWNBOXTEXT` 在 `eventscript.h` 里是 **0 次**），
于是以为"这些指令没有源码"。

实际上 `include/EAstdlib.h` 里每一个都有英文全名：

| 脚本宏 | 语义名 | 意思 |
|---|---|---|
| `LOMA` | `EvtLoadMap` | 加载地图 |
| `FADU` | `EvtFadeOutBlack` | 淡出到黑 |
| `FADI` | `EvtFadeInBlack` | 从黑淡入 |
| `MUSC` | `EvtStartBgm` | 开始 BGM |
| `ENUN` | `EvtWaitUnitMoving` | 等单位走完 |
| `ENUF` | `EvtClearFlag` | 清事件标志 |
| `SENQUEUE1` | `EvtEnqueueFormSlot1` | 入队到槽 1 |
| `BROWNBOXTEXT` | `EvtDisplayPopupSilently` | 静默显示弹窗 |

**缩写不是我要猜的谜题，头文件里用英文写着。**

### 立绘 —— ⚠️ **当前实现是错的，下面是已取证的部分**

**已取证（源码 + 数据双向确认）：**

- `src/Event1E_.c` 的 `Event1E_`（DISPLAYFACE）**字面构造**
  `[位置][LoadFace][脸参数]` 三 token 再交给文本引擎：
  ```c
  gUnk_36.str[0] = subcode + 8;   // 位置码 8..15
  gUnk_36.str[1] = 0x10;          // LoadFace
  gUnk_36.str[2] = evArgument;    // 脸参数
  ```
- `evArgument` 有三个**特殊值**（`s16`）：
  | 值 | 语义 |
  |---|---|
  | `-1` (`$FFFF`) | 从 `gEventSlots[2]` 取 |
  | `-2` (`$FFFE`) | `ClearTalkBubble()` 清气泡，不留脸 |
  | `-3` (`$FFFD`) | `EndEventFaces()` 结束全部立绘 |
- `include/EAstdlib.h:665`：`EvtDisplayFace(slot, fid)` —— **位置与脸是两个独立参数**
- `texts/jp_textdefs.txt` 开头写明：dumper **用的就是这张表**，
  而"多值 / 立绘控制序列"原样输出成 `[$XXXX]`

**数据侧统计（`texts/jp_texts.txt`，4566 个 `[$XXXX]`）：**

| 高字节 | 次数 | 说明 |
|---|---|---|
| `0x00` | 2451 | 槽 0 |
| `0x01` | 2080 | 槽 1 |
| `0xFF` | 32 | **正好是 `$FFFF` = -1**（从槽取），与 `Event1E_.c` 对上 |
| `0x80` | **0** | `textdeparser.py` 的 `$80` 前缀分支**在这个文件里不适用**（dumper 已解成具名 token）|

**所以 `$SSFF` = `(槽位 << 8) | 脸编号` 这个解码是站得住的** ——
序章五个人物逐一核对过：`$0152`=Fado、`$016B`=Soldier_1、`$0102`=Eirika、
`$0104`=Seth、`$0142`=Valter。

**⚠️ 还没定的一点**：文本流里存在 `[OpenFarFarRight][$0080]`
**没有前置 `[LoadFace]`** 的写法（1101 处 `$0080`，多数跟在 `[LF]` 后）。
而 `Event1E_.c` 构造的是**三 token**。所以要么

* `[OpenXXX]` **自带**脸参数，`[LoadFace]` 是可选的；或
* dumper 在某种情况下省略了 `[LoadFace]`

**这一点没定之前不要改实现** —— 已经在"槽位模型"和"位置模型"之间错过两次。

## 五、**验证**也要"先读"

上面七条错误里有两条（门禁、键盘）不是"读错语义"，而是**验证没覆盖到**：

- `check_architecture.dart` 用 `return 1`，而 **`dart run` 不传递 `main` 的返回值** →
  它打印了 1097 处违规却**永远退出 0**
- `test/game/` 下的测试**根本没进验证体系**

**两条铁律**：

1. **每个门禁都要有一次"故意让它失败"的记录** ——
   没有"红过"的门禁，等于没有门禁。
2. **新写的测试必须确认它真的会被跑到** ——
   并且能抓住它声称要防的东西（去掉修复就红）。
