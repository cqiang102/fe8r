# 计划：先补"完整程序"，UI 重构后置

> 由第 106 轮的讨论定下（用户提出：UI 里夹杂了很多逻辑，
> 与其现在重构 UI，不如先移植复刻出一个完整能玩的程序，之后再调 UI）。
> 这份文件是**方向**，不是现状清单。现状清单在 `docs/还差什么.md`，
> 门禁清单在 `tools/verify/run_all.dart`。

## 为什么这个方向对（有实测依据）

| 层 | 规模 | 说明 |
|---|---|---|
| `lib/core`（纯规则）| **60 个文件 / 38109 行** | 有 `PORT OF:` 头、被 R1–R7 强制、**80 个测试文件**覆盖 |
| `lib/game`（Flame 表现 + 编排）| 11059 行 | ⚠️ 其中 **`fe8_game.dart` 一个文件 7488 行**（占 68%）|
| `lib/ui` | 少量 | 界面外壳 |

⇒ **逻辑不是"散在 UI 里"，而是挤在 `fe8_game.dart` 这一个文件里**。
实测例证（第 87 / 101 / 106 轮各一次）：我三次以为某个功能"未实现"，
结果都在 `fe8_game.dart` 里找到了**已经做好的实现**
（設定屏 / 部隊+状況 / 回合触发条件）。

⇒ 所以要做的**不是重写 UI**，而是**把逻辑从那个文件里搬进 `lib/core`**，
一块一块搬、每块都有核心测试。

## "完整程序"的判据（三类，缺一不可）

1. **规则层**：占位符棘轮 + 每个子系统的**纯函数测试**
   —— 现状：棘轮 `3013 → 283`（−91%）、80 个测试文件。
2. **流程层（当前最弱）**：**端到端场景**跑得完、有转储判据
   —— 工具已有：`tools/verify/scenario.sh` + `check_dump.dart`（含 `--selftest`）。
   ⚠️ **但默认门禁不跑它**（要 macos release 构建）⇒ 默认的"通过 N 项"**不含**端到端。
   现状：只有"序章 → 第 1 章"打通过。
3. **数据层**：提取覆盖率 + carve 审计（已有：`carve_audit.dart` / 各提取器计数）。

## 两条**现在就要**守住的护栏（否则"以后再重构"会变成空话）

1. **不新增规则到 `lib/game`**：新逻辑一律进 `lib/core` 并带测试。
   `lib/core` 的 R1–R7 已经在门禁里强制（`check_architecture.dart`）。
2. **`fe8_game.dart` 的规模只许降**：见
   `test/core/layering_ratchet_test.dart`（把逻辑搬进 core 之后，
   就**把那个数字改小**，与占位符棘轮同一个套路）。

## 明确**不做**的事

* **不**为了"将来重构"而提前抽象（那正是浪费）；
* **不**重写现有的 UI（它已经能用；重写会把已经对了的东西再错一遍）；
* **不**把 `fe8_game.dart` 一次性拆掉（先搬逻辑，UI 最后动）。

## 顺带说明：`lib/ui` 的 R6

`check_architecture.dart` 的 R6 是"`lib/ui` 不得反向依赖 `lib/game` 的内部实现"。
这条以后重构 UI 时才有用；现在不用动它。
