## 四、核对"到底做没做"的**唯一可靠办法**

```bash

grep -rn "<关键词>" lib/ --include=*.dart | head
# 2) 再看门禁自己的"尚未实现"段（它是活的）
"$HOME/fvm/versions/<ver>/bin/cache/dart-sdk/bin/dart" run tools/verify/run_all.dart | sed -n '/尚未实现/,$p'
# 3) 最强的判据是端到端（默认不在门禁里，要 --e2e）
"$HOME/fvm/versions/<ver>/bin/cache/dart-sdk/bin/dart" run tools/verify/run_all.dart --e2e
```

## 四·五、工作规矩（用户第 7 轮后明确）：**不做 demo、不"先接后补"**

> 用户原话：**"尽量避免先做demo再补齐，而且结合源码来一次性做好"**。

这条规矩是硬的，具体是四条禁令：

1. **不许"状态层先行"**：凡是只记录状态、不产生真实效果的接线（例：`s.sound(...)`
   记录了"脚本让放第几首"却**一点声音都没有**），**必须**在同一个子系统里
   把"真实效果"一起做掉；做不完就**不要对外说这个子系统"接上了"**，并**明确标注未完成**。
2. **不许留平行实现**：同一件事只留一条路线（例：`searchAvailableEvent` 那条走**原始
   blob** 的路线**没有调用方**，而功能由 `chapter_objectives` 走 `chapters_links`
   的具名表实现 ⇒ 前者要么删、要么**明确标注"记录原件遍历规则、无调用方"**，不许含糊）。
3. **不许"先猜后证"**：动手前必须贴出**处理体的 `file:line`**；贴不出来就**不做**
   （保持占位符），而不是"先实现、标个未查证"。
4. **一次做对的最小单位 = 一个子系统的"数据 → 规则 → 表现"整条链**，
   每段都带判据；任一段只有在**能引用源码**时才写。

⚠️ 之所以写成硬规矩，是因为本会话真的踩过：**3 次在 `fe8_game.dart` 里"发现"
功能早就实现**（設定/部隊+状況/回合触发）、**2 轮把默认难度来回翻**（第 5、7 轮，
两次都更糟）、以及上面那条**无调用方的平行实现**。
