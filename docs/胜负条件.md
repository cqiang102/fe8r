# 胜负条件 —— 机制已找到，实现还没做

> 查「端到端跑通序章 → 第 1 章」时发现：**游戏里没有任何胜负判定**，
> 所以序章打不赢，章节也就永远推进不了。

## 一、原作的机制：`EventListScr_<章节>_Misc`

出处：`src/data/data_08A5A6AD/data_08A5A6AD.s:32-40`

```asm
	.global EventListScr_Prologue_Misc
EventListScr_Prologue_Misc:
	.byte 0x01, 0x00, 0x03, 0x00
	.4byte EventScr_Prologue_EndingScene      @ ← 胜利
	.byte 0x02, 0x00, 0x00, 0x00, 0x01, 0x00, 0x07, 0x00
	.4byte EventScr_Prologue_OneEnemyLeft
	.byte 0x00, 0x00, 0x00, 0x00, 0x01, 0x00, 0x00, 0x00
	.4byte EventScr_GameOver                  @ ← 失败
	.byte 0x65, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00   @ 终止
```

**每一条是「条件字节 + 脚本指针」**：

* 条件字节描述"什么情况下触发"
* 指针指向要执行的脚本

胜利 = 条件满足时执行 `EventScr_<章节>_EndingScene`；
失败 = 执行 `EventScr_GameOver`。

而序章的结束脚本里就是 `MNC2(1)`（切到第 1 章）—— **链路是通的**：

    条件满足 → EventScr_Prologue_EndingScene → MNC2(1) → 第 1 章

## 五、【已解】完整机制

### 遍历（`src/SearchAvailableEvent.c:40-54`）

```c
int cmdId = EVT_CMD_LO(info->listScript[0]);      // 低 16 位 = 命令
if (!CheckFlag(EVT_CMD_HI(info->listScript[0])))  // 高 16 位 = 「已执行」标志
    if (cmdInfo[cmdId].func(info) == 1) goto _end;
info->listScript += len[cmdId << 1];              // ★ 长度由命令决定
```

**`HI` 是「这条已经执行过」的标志** —— 执行后置上，避免重复触发。

### 命令表（`src/data/gEventListCmdInfoTable_ref/*.s`）

| cmd | 名字 | 长度（字）|
|---|---|---|
| 0 | `END` | 1 |
| 1 | `FLAG`（AFEV）| 3 |
| 2 | `TURN` | 3 |
| 3 | `CHAR` | 4 |
| 5 | `LOCA` | 3 |
| 11 | `AREA` | 3 |

### FLAG 条目的结构（`src/EvCheck01_AFEV.c`）

```c
struct EvCheck01 { u32 unk0; u32 script; u32 unk8; };
// unk8 == 0 || unk8 == 100 || CheckFlag(unk8) == 1  -> 执行
```

### 标志枚举（`include/constants/event-flags.h`）

    EVFLAG_ALWAYS_FALSE = 0     EVFLAG_DEFEAT_BOSS = 2     EVFLAG_WIN = 3
    EVFLAG_DEFEAT_ALL   = 6     EVFLAG_GAMEOVER    = 101

### ★ 序章的胜负条件（解出来的结果）

```json
EventListScr_Prologue_Misc:
  {cmd: FLAG, doneFlag: 3, script: 'EventScr_Prologue_EndingScene', checkFlag: 2}
  {cmd: FLAG, doneFlag: 7, script: 'EventScr_Prologue_OneEnemyLeft', checkFlag: 0}
  {cmd: FLAG, doneFlag: 0, script: 'EventScr_GameOver',             checkFlag: 101}
  {cmd: END}
```

* **胜利**：`checkFlag = 2`（`EVFLAG_DEFEAT_BOSS`，击破首领）→ 执行 `EndingScene`，
  并把 `info->flag = 3`（`EVFLAG_WIN`）置上
* **失败**：`checkFlag = 101`（`EVFLAG_GAMEOVER`）→ 执行 `GameOver`
* 中间那条是"只剩一个敌人"的提示

**17 个 Misc 列表全部以 `checkFlag = 101` + `END` 收尾** —— 结构自洽。

### ⚠️ 我在这里绕过一次

我一开始以为末尾的 `0x65` 是**终止符** ——
其实它是**第三条的检查标志**（`EVFLAG_GAMEOVER = 101 = 0x65`）。
真正的终止符是后面那条 `cmd = 0`（END）。

**判据**：按"每条长度由命令决定"分组后，字节数严丝合缝。
