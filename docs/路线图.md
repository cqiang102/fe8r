# 路线图 —— 按**链路**推进，不按机制积累

> 2026 年这一轮的自我复盘：进度一直"碎"，原因是**在按"哪个便宜"挑活，
> 而不是按"哪条链路能合上"**。便宜的是数据/解码/规则层（越做越顺），
> 而"用户看得见"的链路（战斗表现、菜单、大地图）每一块都贵，于是一直没动。
>
> 链路是**与**关系：链上任何一环缺了，整条都不通（教学事件就是例子：
> 入队 + 3 个钩子做完，用户依然看不到任何教学对话）。
> 所以从这份文档开始：**完成 = 一条链路 4/4**。

## 口径

每条链路四列，**四列全绿才允许说"完成"**：

| 列 | 含义 |
|---|---|
| 数据 | 表/脚本/素材已经从 `third_party/fireemblem8j` 提取进管线（有正向计数抽查）|
| 规则层 | `lib/core` 里是**纯函数**、有单测、`PORT OF:` 指到源文件行号 |
| 表现层 | `lib/game`/`lib/ui` 真的画出来 / 真的会动 |
| 判据 | 可重复执行：`scenario.sh` 的转储断言、单元测试、或棘轮（写进 `run_all.dart`）|

**进度指标 = 4/4 的链路条数**（不是占位符棘轮的调用点数——那只量表面）。

## 作业纪律（自我要求，可检查）

1. **一个 run 只动一条边，收尾到这条链路的判据绿**；不在链路之间跳。
2. 回复 **≤ 20 行**：结论 + 数字 + 下一步；细节进 commit 与本文档。
3. "顺手修"进欠账表，按排序做。
4. 每个 run 结束把"下一条边"写进本文档，不靠对话记忆。
5. 只有 4/4 的行才允许写"完成"。
