# 「能不能一模一样复刻原作」—— 算清楚的账

> 用户问：**那能一模一样复刻原作的吗**
>
> 答案分两半：**一半已经可以确定精确复刻；另一半在本仓库范围内做不到。**

---

## 一、已经**能**精确复刻的

### 1. 全部逻辑 —— 精确度 100%

反编译项目的门禁是 `make compare`（与 ROM **逐字节一致**）。
所以规则、公式、流程、常量**不是"接近"，是精确已知**。

这也是本项目从第一天起就在做的事：`lib/core` 1:1 端口 + C Oracle 对照
（1104+ 向量，全部通过）。

### 2. 全部文字 —— 3339 条消息

`texts/jp_texts.txt`（Huffman 已解）+ 消息 id 表。**原文可得。**

### 3. 全部地图 —— 52 张

`map_tmx.py` 导出并做**往返验证**（"616 格 metatile 与地形类型全部一致"）。

### 4. 图形 —— 仓库里已有的那部分

| 类别 | 数量 |
|---|---|
| `opanim/`（职业介绍 / 开场动画）| **165** |
| `portrait/`（立绘）| **323** |
| `efxdragon/`（特效）| **64** |
| `reuse/`（剧情背景）| **52** |
| `gfx_data_bg/`（剧情背景）| **43** |
| `btl_bg/`（战斗背景）| **28** |
| `misc_gfx3/IntelligentSystems.png` | 1 |
| **合计** | **676** |

**这 676 张是"可编辑的合成源图"**（`Makefile:804-808` 用 `$(GBAGFX)` 转成
`.4bpp`/`.gbapal`）—— 直接用就是精确的。

### 5. 所有布局坐标

菜单的 X / 居中公式 / 行距 / 括弧位置 / 文字列行 —— **都在源码里**
（见 `docs/菜单盘点.md`）。

## 二、**做不到**的

### 1. `Img_*.png` 的图块排布 —— **265 张**

这些是"裸图块条"，需要 **FETSATOOL 的反向（拆分）**。

而反编译项目自己的 `graphics/opanim/opanim.mk` 写着：

> The FE-specific `.feimg4.bin.lz` / `.fetsa4.bin.lz` assets
> … **need the FE TSA-splitter tool (FETSATOOL), which this repo does not yet have**,
> so they are HONESTLY left as `.incbin "baserom.gba"` pending that tool.

**我解出了 ×17 规则**（`L` 模式 PNG 是 4bpp 按 `n*17` 展开的，
四张素材 0 例外）—— 这是必要的一步，但**还不够**：还差
「TSA 项 / OAM 精灵 → 图块」的映射。

### 2. 反编译**没有 carve** 的数据

例如 `SaveDrawCursorYOffsetLut`（浮动波形）—— 只有地址 `081F57F1`，
**8 个字节不在仓库里**。

### 3. `baserom.gba` 不在本地，且 `.gitignore` 里从不提交

所以第 2 类**无法从仓库恢复**。

## 三、结论

| | 状态 |
|---|---|
| 逻辑 / 文字 / 地图 / 表格 | **可以 100% 一样** |
| 已合成的 676 张图形 | **可以 100% 一样** |
| 265 张裸图块 | **目前不行**（差拆分工具的排布那一步）|
| 未 carve 的数据 | **不行**（数据不在仓库里）|

**大约 72% 的图形素材已经在手（676 / 941）。**

## 四、要真正做到"一模一样"，两条路

### A. 用 ROM（用户自备 `baserom.gba`）

任何资产都能**从地址精确提取**，包括未 carve 的那部分。

* 优点：一次性解决全部
* 约束：**这是从 ROM 提取内容，只适合个人研究，不能分发**
  （我们此前的共识是"个人学习、不发布"，所以这条在范围内）

### B. 继续解 `Img_*` 的排布

×17 已解，差「TSA 项 / OAM → 图块」的映射。

* 优点：**完全在仓库范围内**，产出的是可分发的内容
* 已确认自洽的部分：`Tsa_DifficultyMenuObjs` 头 `0x0B0C` = 13×12 = 156 项，
  文件 314 字节精确吻合

---

## 五、我的建议

**做 B，但要换方法。**

我在 `Img_*` 上烧了很多轮，共同点是**在数据里试参数**。
而 `tsa_generator.py` **就在仓库里**（Makefile:241）—— 它是**正向**工具
（PNG → `.feimg4.bin` + `.fetsa4.bin`）。

**把它跑起来，用一张已知的合成 PNG 生成一对 `feimg4`/`fetsa4`，
再拿那份 `fetsa4` 去反推排布** —— 这样是**用工具定义格式**，
不是猜参数。这是我一直没做的一步。
